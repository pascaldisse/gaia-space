## C · native visibility fact

TRUE: organizer does **not** need a participant row. `MEETING_READ_SCOPE`, `src-tauri/src/meetings.rs:185-194`, allows `m.organizer_id=?1` independently. Participants visibility additionally permits a matching `meeting_participants` row; public permits all; participants+project channel permits project creator/member. List binds acting profile through `visible_meetings_on`, `:228-246`, exposed by `list_meetings`, `:321-325`.

Thus: `visibility="participants"` + organizer identity equals acting profile => visible with zero invitees. `organizer_id=null` + zero self-invite + no qualifying project channel => invisible after create/list; no participant self-registration occurs in client paths.
